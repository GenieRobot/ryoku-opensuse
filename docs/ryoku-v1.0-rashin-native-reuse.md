# Retained native Rashin source and Tumbleweed recipe

Issue #173 now supplies a declarative `ryoku-rashin.spec` for the retained
upstream Go backend, embedded Svelte console and C++ GTK3/WebKitGTK companion.
The shared implementation stays upstream; narrow openSUSE authorization,
package, account and linked recovery boundaries remain Rust integration work
under #183. Complete Rashin functionality remains a release target.

This is a private, unselected build candidate. Its libexec executables, usage
collectors, skills, wiki and repository context are real upstream inputs;
public aliases, launchers and active user units await the tested #183 route.
The desktop metapackage and ten-package production audit retain their current
selection. Nothing in this slice certifies an installed or functional Rashin,
removes a required capability, or completes #173/#183.

## Exact inputs and reproducible context

Upstream remains Ryoku Amaterasu **1.0.0**, commit
`a59d051f0e8080052216f6c7b9eb7e5928935ce8`, tree
`06b2962f82f43118c3a98372c2a4b435b689b725`. Port RPM **0.1.0-8** follows the
independent co-versioning policy; it is not the major upstream version.

The recipe consumes the unchanged Source3 SHA-256
`387d829860ba844ad32ecdd5982678707665f3251e41bbb43c6fd6f87dc7eee0`, including
all 338 core Rashin source entries, committed Go vendor, embedded web dist and
shared WM source. Source2 is unchanged. The original frontend lock, eight
source/dist byte-identical font pairs, websocket ISC notice and font OFL notice
remain bound by the [source metadata](../packaging/rpm/rashin/ryoku-rashin-source-a59d051.json)
and package tests. The embedded frontend is retained without a Node download
or rebuild. Complete JavaScript dependency notices/source reconstruction are
still open; the recipe marks that unresolved license boundary explicitly.

The shipped [repository context](../packaging/rpm/rashin/ryoku-rashin-context-a59d051.md)
is generated by the unchanged pinned `repo-index` implementation from the
**complete** clean upstream tree: 8,874 regular files (451,119,868 bytes) plus
26 literal Git links (1,336 bytes). Source3 alone would omit important docs,
system, installation and release context. Two runs with Git unavailable in
PATH reproduce the same 2,453 bytes, SHA-256
`7441655d8f9d384f4e1b292d6e44de3a2c4fbccf097108e09578927602ec97d8`.
This omits only the generator's optional live Git/time header. The recipe
checks the archive, context and metadata digests before extraction.

## Measured checks and limits

Using the existing extracted Tumbleweed Go 1.26.9 SDK, the backend builds from
digest-verified Source3 with `GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off GOWORK=off
CGO_ENABLED=0`, `-trimpath -mod=vendor -buildvcs=false`. The resulting static
x86-64 ELF is 13,586,959 bytes, SHA-256
`7b5eb38b2a0bea933fddaf4904bf2dc286877e49c17874272a71d5c79d97f9b1`.
Its two repository-index fixture tests pass. Their unchanged `TestMain`
reserves an ephemeral loopback port, so the initial restricted-sandbox attempt
failed before either test; the same tests passed with local socket access.
The daemon, collectors and external agents were not launched.

Native `rpmspec` parsing and dependency queries pass. The recipe copies the Go
BSD notice from the cached provider's actual
`/usr/share/doc/packages/go/1.26/LICENSE` path using `_defaultdocdir` and the
GOROOT basename. Focused tests enforce its resolved license path, private
install selection, source/context digests, retained fonts and absence of
package scriptlets or build-time package dispatchers.

BuildRequires-enabled RPM preparation fails before `%prep` because the host
RPMDB lacks Go, CMake, Ninja, GTK3 and WebKitGTK development providers.
No dependency closure was downloaded or installed. Separate `--nodeps -bp`
mechanics with scratch `_topdir`/`_tmppath` pass all three digest checks and
archive extraction. This does not establish native build acceptance. GTK/WebKit
compilation, full RPM/SRPM artifacts, automatic ELF dependencies, signed solver,
installation and loading remain unverified. The [validation record](../upstream/evidence/ryoku-v1.0/rashin-native-reuse-validation.json)
preserves commands, source identities and both environment failures.

The same candidate refreshes the cached RPM metadata decompressor to zstd
0.14.3 / zstd-safe 8.2.0 / zstd-sys 2.1.2 and reviews their BSD-3-Clause notices
for dependency policy. Its existing default features and metadata API stay the
same. Locked offline workspace tests, strict Clippy, formatting, the two native
spec-parser checks and offline dependency review pass.

Prowl/Hermes closure, complete embedded frontend notices and source rebuild,
#183 authenticated native transport/account/collector/write/recovery
integration, full semantic/API review and the fresh combined #25/#26 acceptance
remain required. No Fedora dispatcher/scriptlet, package-manager workflow or
new project-owned non-Rust executable is imported. No source download, package
installation, VM access or user service activation was performed.
